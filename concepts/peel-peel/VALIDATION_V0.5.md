## 新原型
[Endless Peel V0.5 HTML](https://github.com/ChengK321/Kai-Game-Design/blob/concept/peel-peel/concepts/peel-peel/prototypes/endless_peel_v0.5.html)

### 两个独立可切换变量
**连锁规则：**
- none 原版：只剥离每条队列两端所有连续外露的选中色块；
- v3 纵向三连：先按原版标记被选中色块，再按**原始未消除棋盘坐标**连接同一列连续至少 3 格同色且接触初始标记的部分，全部一起消除；不在压紧后循环重新引爆；
- vall 纵向全连：用于研究极限爽感，尚不推荐正式采用。
**补块规则：**
- A 原版：4色、容量8，每回合四个方块独立均匀随机分配行；与 V0.4 Seed 1029 预生成逻辑兼容。
- A2 温和均衡：4色、容量8、每回合**总共4块**，且同一行最多新增2块；这**不保证**永远存在安全操作。
- A3 强保护：同 A2，但新一轮补块预告在公布前检验**是否至少存在一种选色，结算后不即时超容量**；如果理论上存在容纳四个新块的安全方案，则选出满足条件的方案；如果任何方案都无法容纳四块，不会强行创造规则以外的逃生机会。用户仍可能选错颜色直接失败。属于实验性改变随机分布，不是正式答案。
- B 对照：5色，容量9，每排固定新增1块。

### 解决 A / Seed1029 / 第38回合的具体问题
- 可通过前台“复现第38回合”按钮一键重放上传的A模式1029种子前38步选色序列，直接显示 **5/7/7/1** 的队列长度和**所有合法选择都会立刻失败**的状态；
- 此为**有据可查的旧版无解局面**，不是纯UI错觉；
- A2 减少单回合 3～4 块随机砸向一排的尾部风险，但没有从数学上根除无解；
- A3 会在当前状态下能布置合理补块时，避免系统**预先公布一个让所有颜色当即必败的补块计划**，因此对这类随机必死回合有针对性帮助。但玩家的历史选色仍然可能导致物理上不存在任何容纳4块的行分布，此时仍可能失败；
- 失败后完整画出超容量的第9块（原 V0.4 被截断），在提示区明确显示哪一排 X/8 溢出；本次颜色按钮的真实危险状态也可即时显示。
- 两种修复面向不同根因：风险信息呈现和随机补块分配；不可称为已经彻底消除所有死局。

### 纵向三连已复核
用户截图对应棋盘（以R红/B蓝/Y黄/P紫/G绿）：
`RRBGPGP / GRY / PRYGPR / YRGBR`。
选择红色时：原版4块（第1行左侧2、第3和第4行右侧各1）；v3 扩展到第2～第4行的第2列红块，总计 **7块**。在移动压紧前判定，保持规则确定性。

## 实际浏览器测试（FACT / ENGINEERING）
- Chromium / Playwright：桌面 1180px 和手机 390px 两种宽度，无水平溢出与 JS runtime exception。
- 默认棋盘初始化、种子重开、A/B模式切换、预告与实际补块一致；棋盘动作在计分后正确更新。
- V0.4 Seed1029 A 原版第38回合完整重放：**长度 5/7/7/1**、全部合法颜色死亡；实际执行后溢出格可见、死亡原因文字显示。
- 用户红色截图局面：none消除4，v3消除7（基本端点4＋纵向3），vall至少7。
- 60 seed (1000..1059), 120回合上限，采用“**只选本轮安全颜色，并在安全集合中优先选消除最多的颜色**”策略测试原版纵向关闭：A中位34、A2中位47、A3中位达到120上限、B中位47。该策略使用当局即将补入的所有块预测安全性，因此远强于完全不看提示的真实玩家，不得当作真人难度估计。
- 上述结果中 A3 的60种子没有出现“已经计算存在安全颜色却预告成全死”的情况。**A3很容易被这种策略长期存活**，这是它不宜直接作为默认玩法的重要反证。

## Evidence Red Team
- A3 事实上改变了随机生成的难度分布，让所有颜色都死的结构被主动剔除。它减少无理挫败的同时，也可能把策略要求简化为“只避免红框”。不要误认为分配更公平就一定更好玩。
- A2 偏温和，也不保证能抵抗玩家主动将危险行长时间留满；仍存在必死局面。
- 即使纵向三连给出更多爽感，它同样可能使存活时间增长到无紧张感；本次不要同时换出生规则和连锁来断言某一因素带来的提升。
- 完全保证所有玩家“再下一步都有解”，将取消死亡风险；本原型只是使系统公布的当轮补块可控，不承诺任何历史局面可挽回。
- 统一展示“当前颜色会造成溢出”属于辅助，可能增加界面复杂度和解题导向，可关闭并对照。
- 该原型没有真实 D1/D7 留存、陌生玩家复玩率、传播数据，不可称为确定的爆款。

## 试玩顺序（尽量单变量）
1. 用顶部“复现第38回合”看A旧版问题，尝试各颜色，理解旧结算。
2. 同种子对照 **A vs A2**，保持连锁为 none，观察是否减少一排瞬间被砸三四块。
3. 固定 A2，比较 **none vs v3**，只评估点击的可理解性、连消反馈、思考负担，控制其他设置不变。
4. 如A2仍出现大量令人不解的全死局，才试玩 A3，记录“是否太容易”。A3 不宜先作为默认。

## Kill / Upgrade
- 若 A2 游戏仍经常在无预兆下出现无可选操作，应继续检查候补逻辑；不能仅以平均生存增加评估成功。
- 若 v3 玩家第一眼不能预测消除范围、花太久看列坐标，退回原版而不是加更多规则/道具。
- 若 A3 让玩家持续存活但单局没有变化、没有紧张感，直接退出 A3。
- 原型仅研究核心机制，不引入关卡、技能、广告、美术资源堆叠。

## 当前决定
**A2 + v3 为默认对照组合（不是最终定稿）；保留 A/none 历史可复现基线；A3 为压力边界实验。**
